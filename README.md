# Freedom CQA

Локальный прототип Conversation Quality Analytics для CQA Hackathon: FastAPI, GPT-4o и HTML/CSS/JavaScript без сборки. Проверка качества, апелляции, практика по ошибкам и AI-помощник руководителя. Внешние AI-запросы проходят через общую серверную подготовку, скрытие найденных персональных данных и подтверждение фактического содержимого.

## Запуск

Требуется Python 3.10+. Из корня проекта в PowerShell:

```powershell
.\start.ps1
```

При первом запуске скрипт создаёт `.venv` и устанавливает зависимости. Для повторной установки: `./start.ps1 -Setup`. Альтернативно:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Интерфейс: [localhost:8000](http://127.0.0.1:8000). Документация API: [/docs](http://127.0.0.1:8000/docs).

На подготовленном Mac двойной щелчок по `start.command` запускает приложение и открывает сайт. Для ручного запуска используйте `.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --workers 1`.

На этом компьютере `.env` и `data/dev_dataset.json` уже подготовлены из предоставленных материалов. В чистой копии сначала скопируйте `.env.example` в `.env`, заполните `OPENAI_API_KEY` и импортируйте файл организаторов:

```powershell
python scripts/import_dataset.py "C:\path\invoke.json"
```

Файл должен содержать успешный ответ `isSuccess: true`, `data.records`. Импортируйте до первого запуска. При существующем хранилище записи берутся из него; для загрузки или обновления группы используйте «Настройки → Источник диалогов и служебные настройки → Обновить из источника». В `.env` задайте полученный от организаторов `DATASET_URL`; подпись URL не публикуется в репозитории. `group_id` меняется через настройки. Наборы хранятся вместе: обновление группы заменяет только её записи. Вкладки «Все диалоги», DEV, FBroker и SWAP переключают список, аналитику, апелляции и область поиска помощника без повторного скачивания. Исходные ID и переписки сохраняются; оценки и история других наборов не изменяются. SWAP доступен для просмотра, одиночная и пакетная оценка заблокированы до отдельной инструкции организаторов. Переключение наборов не вызывает OpenAI. Без сети доступны кэшированные диалоги и оценки; для первой загрузки аудио и новой оценки сеть нужна.

## Экономия API

- `OPENAI_MAX_CALLS=3` — общий постоянный потолок попыток, а не лимит на перезапуск. Счётчик хранится в `data/data_store.json`, резервируется **до** запроса. Не удаляйте хранилище ради сброса бюджета.
- Автоматических повторов SDK нет (`max_retries=0`). Ошибка тоже расходует попытку. На каждый ответ установлен `OPENAI_MAX_OUTPUT_TOKENS=2600`.
- Выбор диалога, обычные фильтры, просмотр, апелляции и пересчёт весов API не вызывают. Поиск естественным языком через AI-помощника расходует запрос; повторное применение уже полученных структурированных фильтров выполняется локально. Актуальная оценка возвращается из кэша. Явная кнопка повторной оценки использует `force=true` и расходует вызов.
- Изменение только весов пересчитывает актуальные оценки локально. Изменение правил, шкал, названий, состава критериев или N/A переводит предыдущие оценки в `Stale`. Их нужно запускать отдельно, по одной или ограниченным пакетом. Это осознанное ограничение для сохранения бюджета пользователя, а не автоматическая обработка всех 65 записей.
- Для работы без ограничения количества проверок задайте `OPENAI_MAX_CALLS=unlimited` и перезапустите сервер. Этот ранее разрешённый пользователем режим сохранён на данном компьютере; новая функция его не меняет. Счётчики вызовов и токенов продолжают сохраняться. Числовое значение возвращает ограничение; `0` запрещает новые запросы. Общий бюджет распространяется на анализ диалогов, упражнения, поиск и рекомендации помощника; он не заменяет ограничения провайдера API.
- По просьбе пользователя отдельный потолок 20 запросов помощника снят: `OPENAI_ASSISTANT_MAX_CALLS=unlimited` в локальных настройках и по умолчанию. Каждая попытка по-прежнему учитывается в отдельном и общем счётчиках, включая ошибки. Числовое значение позволяет явно вернуть отдельный потолок; общий числовой лимит и запрет внешней обработки действуют независимо. Счётчики при перезапуске сохраняются. Размеры ответов и остальные ограничения не увеличены.
- `OPENAI_ASSISTANT_MODEL` задаёт модель помощника отдельно; без значения используется `OPENAI_MODEL`. `OPENAI_ASSISTANT_MAX_OUTPUT_TOKENS=900` ограничивает ответ помощника и дополнительно ограничен меньшим значением `OPENAI_MAX_OUTPUT_TOKENS`. Инструкции поиска и выбора приоритетов отделены от инструкций оценки диалогов.
- Интерфейс показывает токены ответов, для которых получен usage, включая отклонённые валидатором. При сетевом обрыве провайдер также мог начислить токены; локальные цифры не заменяют биллинг провайдера. В первой тестовой версии usage отклонённого EN-ответа не сохранялся, поэтому для него число токенов неизвестно.

## Интерфейс

Кнопка «AI-помощник» имеет отдельную иконку бота и подпись на RU/KZ/EN. В панели отображается фактическое состояние бюджета: без ограничения количества запросов, оставшиеся попытки при числовом потолке или запрет внешней обработки.

По умолчанию включена светлая тема. Кнопка в шапке переключает светлую и тёмную темы; выбор сохраняется в браузере. На рабочих экранах используются короткие подписи. Подробные правила каждого критерия раскрываются отдельно в редакторе.

Переключатель RU / ҚАЗ / EN меняет язык интерфейса, сохраняя выбор в браузере. Язык интерфейса независим от языка выбранного диалога. Исходная переписка, цитаты, комментарии аудиторов и пользовательские правила не переводятся: это доказательства и рабочие данные.

### Скриншоты и фотографии чатов

В «Загрузить диалог» доступны JSON, TXT, DOCX, текстовый PDF, PNG, JPG/JPEG и WebP до 5 МБ. Изображения распознаются локально на macOS через Apple Vision: платных запросов OpenAI нет, фото не отправляются во внешний сервис и не сохраняются сервером. Предел изображения — 24 мегапикселя. Для первого запуска нужны Command Line Tools (`xcrun swiftc`); подготовленный распознаватель кэшируется в игнорируемой папке `output/`.

После распознавания проверьте текст в редакторе, уберите элементы интерфейса со скриншота и подпишите реплики `Клиент:` / `Оператор:` (также поддерживаются `Client:` / `Operator:` и `Тұтынушы:` / `Маман:`). Временные метки необязательны. Система не угадывает участников по расположению пузырьков и не создаёт реплики до явного сохранения. Казахские символы проверяйте особенно внимательно: текущая версия Apple Vision на этом Mac поддерживает русский и английский, но не отдельную казахскую модель. На других ОС можно вставить текст вручную или загрузить документ/JSON.

Распознавание текста: [официальная документация Apple Vision](https://developer.apple.com/documentation/vision/vnrecognizetextrequest).

### Рекомендации и практика

У каждого актуального критерия со сниженным баллом или грубой ошибкой появляется рекомендация и кнопка «Отработать навык». Новые оценки OpenAI содержат конкретный совет и задание по выявленной ошибке в том же запросе оценки. Если модель оставила рекомендацию или упражнение пустыми либо превысила лимит их длины, проверенная оценка сохраняется, а приложение использует локальную подсказку по действующему правилу с меткой «На основе правил». Дополнительного AI-вызова нет. Для изменённого пользователем критерия используется нейтральное задание по его собственной формулировке. Подсказки модели для полностью выполненных критериев и N/A отбрасываются без изменения баллов. Проверка значений, обоснований, ссылок и цитат остаётся обязательной. Старые результаты также используют подсказку по действующему правилу; после ручного решения по апелляции исходный совет ИИ заменяется подсказкой по правилу. Для N/A, полностью выполненных и устаревших критериев упражнение не предлагается. Руководитель видит рекомендации без кнопки прохождения упражнения.

В упражнении показаны правило, исходная ошибка и контекст до заменяемой реплики. Оператор пишет новый ответ и явно нажимает «Проверить ответ». ИИ проверяет только этот критерий, объясняет, что получилось, что исправить и почему. Статус «Упражнение выполнено» соответствует максимальной ступени критерия (для флага — отсутствию нарушения), иначе «Нужно доработать». Обратная связь формируется на выбранном языке интерфейса; переписка и цитаты не переводятся.

Открытие рекомендаций и упражнения бесплатно. Каждая новая проверка ответа расходует один запрос из **общего** `OPENAI_MAX_CALLS`, включая ошибки; повторы SDK отключены. Повтор идентичного ответа на том же языке возвращает сохранённый результат без запроса. История практики хранится отдельно в `data_store.json` и не изменяет баллы, апелляции или транскрипт. Изменение правила, исходного диалога, оценки или решения по критерию делает открытое упражнение неактуальным. Если состояние изменилось во время вызова, устаревший результат не сохраняется, но выполненная попытка учитывается.

API: `GET /api/practice/{conversation_id}/{criterion_id}` — задание и история; `POST` на тот же путь — `{exercise_key, evaluation_id, answer, language, request_id}` с заголовком `X-AI-Preview` для новой проверки. Превью сначала готовится через `POST /api/ai/prepare` с назначением `practice`, ID диалога и критерия, ответом и языком. `answer` — до 5000 символов, `language` — `ru/kk/en`, `request_id` — UUID для защиты от повторного списания при сетевом повторе. После явной ошибки ИИ новая осознанная попытка использует новый UUID и актуальное превью; неизменный UUID повторного запроса не запускает ИИ снова.

Проверка текста не доказывает выполнение реальной процедуры или соблюдение времени ответа. Модель должна отмечать это ограничение, а смысловую точность обратной связи проверяет аудитор. Формат ответа использует [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и дополнительную проверку допустимого значения и точной цитаты из нового ответа.

### AI-помощник руководителя

Боковая панель содержит историю, поле запроса, примеры, состояние обработки и сообщения об ошибках. Помощник доступен руководителю; проверка роли и настроенного токена выполняется сервером. Он не редактирует чек-листы, результаты, решения по апелляциям и не назначает наказания.

Поиск естественным языком преобразуется моделью в команду из разрешённых фильтров и сортировок. Например: «Покажи грубые ошибки», затем «Только на русском», «Оценки ниже 60», «Какие разговоры ещё не проверены?», «Апелляции, ожидающие решения». Уточнение дополняет активные условия. Сервер проверяет структуру и значения; сгенерированный SQL или код не исполняется. Условия применяются к основному списку, их можно сбросить; обычные фильтры сохраняются. Неоднозначный или неподдерживаемый запрос приводит к уточнению.

Для распознавания поисковой команды внешней модели передаются только запрос, текущие условия и краткое описание доступных команд/критериев. Тексты разговоров и оценки для этого не передаются. Количество результатов, сортировка и ссылки вычисляются сервером. Причины берутся из сохранённых результатов; переоценка не запускается. Запрос об отсутствии представления ищет явные формулировки в сохранённых обоснованиях на RU/KZ/EN: ошибка составного критерия «приветствие и представление» сама по себе не доказывает отсутствие представления. Такой поиск может пропустить неоднозначное обоснование, что отмечается в ответе.

По кнопке приоритетов или запросу «На что обратить внимание?» предлагается до трёх действий: проверить разговор, разобрать повторяющуюся ошибку на обучении или рассмотреть разногласия по критерию. Для этого отдельно готовятся агрегаты и короткие обоснования, которые также проходят скрытие данных. Модель выбирает только существующие ID приоритетов; наблюдения, количества, размер выборки, ссылки, действие и цель берутся из серверного каталога. Полные разговоры ей не отправляются. Если запрос поиска распознан как запрос рекомендаций, подготовка агрегатов и подтверждение их отправки выполняются отдельным действием, без скрытого второго AI-вызова. Недостаток данных показывается явно; гипотезы, потери денег, вероятность ухода клиента и показатели сотрудников не выдумываются.

Поиск и приоритеты используют **финальные актуальные оценки после апелляций**, исходная AI-оценка показывается отдельно. Различаются `Нет`, `N/A`, отсутствие оценки (`Pending`), выполняющаяся обработка (`Evaluating`), ошибка без актуальной оценки (`Error`) и устаревшая оценка (`Stale`). Ошибка повторного анализа не отменяет сохранённую актуальную оценку. Охват вида «Оценено 20 из 65» не включает остальные записи в число проверенных. Для частоты ошибки по критерию знаменатель содержит только применимые текущие оценки; исключённые N/A указаны отдельно. Разговоры не объединяются по сотрудникам без надёжных идентификаторов. DEV-набор помечен как синтетический, его результаты не являются показателями компании.

### Защита исходящих данных и «Что получит AI»

В настройках есть два независимых серверных переключателя:

- **«Скрывать персональные данные перед отправкой AI»** — включён по умолчанию. Подпись: «Система скрывает найденные персональные данные. Автоматическая проверка может пропустить сведения; подготовленное содержимое передаётся внешнему AI-провайдеру».
- **«Запретить внешнюю AI-обработку»** — блокирует все новые внешние вызовы: одиночную, пакетную и повторную оценку, помощника, приоритеты и практику. Локальная модель сейчас не настроена, поэтому автоматический анализ при запрете недоступен. Просмотр сохранённых данных, обычные фильтры, апелляции и ручная работа сохраняются.

Скрытие выполняется локально до внешнего запроса. Обнаруживаются ФИО по контексту и шаблонам, ИИН, телефоны/email, адреса, счета/карты, пароли и одноразовые коды. В пределах подготовленного диалога повторяющееся значение получает одно обозначение, например `[КЛИЕНТ_1]`, `[ИИН_1]`, `[ТЕЛЕФОН_1]`. Система не заменяет все числа подряд: сроки, тарифы и суммы должны оставаться доступны для оценки. Роли, ID/индексы сообщений, время, факт представления и идентификации сохраняются; оригинальный транскрипт не изменяется. Таблица соответствий не передаётся провайдеру.

Перед новой отправкой кнопка **«Что получит AI»** показывает фактически подготовленный запрос, включая инструкции, модель, параметры и текст. Можно добавить до 40 значений для дополнительного скрытия, каждое длиной 1–200 символов. После изменения сервер формирует новое превью; подтвердить нужно именно его. Если подготовка не удалась, данные или настройки изменились либо превью истекло, отправка блокируется. Автоматической отправки оригинала и резервного обхода защиты нет. Предпросмотр сам не вызывает модель и не расходует попытку.

Проверка доказательств сохранена: точная цитата сверяется с отправленным текстом и затем связывается с оригинальной репликой по ID/индексу и локальной карте замен. Неподтверждённая цитата или цитата, обрывающая скрытое значение, отклоняется. Первая версия обрабатывает только текст; внешняя отправка необработанных аудио и изображений блокируется. Локальный просмотр, прослушивание и локальное распознавание скриншотов остаются доступны.

**Ограничение распознавания:** это эвристики, а не гарантированное обезличивание. На RU/KZ/EN лучше распознаются имена и адреса с явными метками или типовыми формами. Возможны пропуски одиночных имён, инициалов, склонений, транслитерации, смешения языков, опечаток, нестандартных казахских ФИО и свободно записанных адресов; возможны лишние замены. Точность на реальном корпусе не измерялась. Просматривайте подготовленный текст и дополнительно скрывайте пропуски. Функция не подтверждает соответствие законодательству РК.

Ключ OpenAI хранится только на сервере; браузер, превью и технический журнал его не получают. В журнал исходящих вызовов входят ID диалога (когда применим), время, провайдер, назначение и режим защиты, без полных запросов и таблиц соответствий. Исходные данные и рабочая история остаются в локальном хранилище приложения. Для поддерживаемых вызовов передаётся `store: false`; это **не гарантия полного отсутствия хранения у провайдера** и не замена проверки его условий обработки данных.

1. Чтобы показать классификации грубых ошибок, включите фильтр «Грубые ошибки» или перейдите из аналитики. Фильтр учитывает только актуальные оценки; причины вынесены в начало карточки. Выберите диалог, язык RU/KZ/EN или канал. В роли «Руководитель» нажмите «Оценить диалог». Если тестовый бюджет исчерпан, используйте уже оценённые записи.
2. Откройте критерий: исходный вес, нормированный вес, полученные баллы, обоснование и цитата. Нажмите время: переписка прокрутится; для звонка запись загрузится и перемотается относительно первой реплики. ISO-время показывается в UTC, журнал — UTC+6.
3. Переключитесь на «Оператор», нажмите «Оспорить оценку», введите основание.
4. Вернитесь в роль «Руководитель», рассмотрите апелляцию, удовлетворите с новой оценкой/N/A либо отклоните. Итог пересчитывается сразу. ИИ-обоснование сохраняется отдельно от причины ручного решения. В журнале есть предыдущий и новый результат.
5. В редакторе измените вес и сохраните. Итоги пересчитаются без API. При изменении самого правила предыдущий результат останется виден с пометкой о необходимости переоценки. Можно добавлять и удалять критерии.

## Расчёт и валидация

Восьмикритериальный исходный чек-лист воспроизведён из `CQA_Chat_Quality_Checklist.pdf` (стр. 1–3). Базовые веса: 10, 15, 20, 20, 15, 15, 5, 0. Ступени консультации: 0/5/10/15/20; ведения диалога: 0/4/7/10. Грубые ошибки имеют нулевой вес и отдельный флаг, итог не обнуляют.

Для применимых критериев с баллами:

```text
S = сумма базовых весов применимых критериев
нормированный вес_i = вес_i / S × 100
баллы_i = значение_i / максимум_шкалы_i × нормированный вес_i
итог = round(сумма баллов_i, 2)
```

Для бинарной оценки максимум равен 1. Если `S = 0`, итог `null`. Промежуточные значения не округляются; итог считается через `Decimal` с `ROUND_HALF_UP`. Пример: 02 и 03 = N/A, 04 = 10, 06 = 7, остальные балльные критерии = Да. Тогда `S = 100 − 15 − 20 = 65`; заработано до нормирования `10 + 10 + 15 + 10.5 + 5 = 50.5`; итог `50.5 / 65 × 100 = 77.69`.

ИИ не считает арифметику. Сервер проверяет ровно один результат на критерий, разрешённые ступени, допустимость N/A, существование реплики, точное вхождение цитаты и совпадение времени. Невалидный ответ не сохраняется как оценка. Точное вхождение цитаты подтверждает источник, **но не гарантирует правильность смысловой оценки**; требуется проверка аудитором. Bot/system — контекст; системное подтверждение идентификации может быть доказательством.

Инструкции оценки приведены к подробным правилам пользователя в `backend/evaluation_policy.py`, версия `2026-11-08.3`: первый ответ человека, известная боту потребность, порядок идентификации и раскрытия данных, все существенные вопросы, исправленная консультация и отдельный сбой ведения диалога, завершение по нескольким репликам, три основания грубой ошибки и ограничения текстовой оценки звонков. Изменённая пользователем формулировка критерия имеет приоритет над базовыми пояснениями; изменение только веса их не отключает.

Для исходного чек-листа модель возвращает коды `contact`, `discovery`, `identification`, `consultation`, `empathy`, `dialogue`, `closure`, `critical`; бинарные значения — настоящие JSON boolean. Адаптер сохраняет совместимость с ID `01`–`08` и числовым хранением 0/1 для формулы, апелляций и экспорта. `rationale` содержит краткое обоснование, `evidence_turns` — номера всех необходимых реплик с 1, включая client/operator/bot/system. В запросе есть только одна нумерация — поле `turn`; внутренний индекс с нуля модели не передаётся.

В протоколе `source-turn-v3` модель выбирает `proof_turn` из `evidence_turns`. Сервер берёт точный фрагмент до 180 символов и время из выбранной отправленной реплики, проверяет дословное вхождение, затем восстанавливает цитату через карту того же исходного сообщения. Фрагмент не обрывает обозначения скрытых данных. Модель больше не перепечатывает цитату и время: такие лишние поля, несуществующие номера и ссылки вне `evidence_turns` отклоняются. Для исходного `contact` основная ссылка ограничена первым непустым ответом человека-оператора; пользовательские изменённые критерии этого ограничения не наследуют. Проверка источника сохраняется, но смысловую связь обоснования с цитатой должен оценивать аудитор. Дополнительные ссылки доступны в интерфейсе. Указанное в записи поле `reference_materials` проходит ту же защиту и передаётся как данные. В текущих 65 DEV-записях справочные материалы отсутствуют; продуктовые факты нельзя считать проверенными только по памяти модели.

Для длинных звонков номера реплик ограничиваются диапазоном `minimum=1, maximum=N`, а не повторяющимися списками `enum`. Для первого ответа оператора по `contact` сохранён единственный допустимый номер. Это устраняет превышение общего лимита 1000 enum-значений: у p4-ru-003 (78 реплик) прежняя схема содержала 1193 значения, новая — 23. Вся расшифровка передаётся без обрезки, сервер по-прежнему проверяет целые номера, диапазон, принадлежность основной ссылки к доказательствам, цитату и время. Перед отправкой действует локальная проверка размера enum для всех AI-запросов; сложный пользовательский чек-лист отклоняется до списания попытки. Ошибка параметров провайдера сохраняется отдельным безопасным кодом `provider_request_error`, без тела ответа и без автоматических повторов. Подготовка всех 65 текущих записей и синтетические одиночная, пакетная и повторная оценки длинных звонков проверены без платных API-вызовов.

При объективно недостаточных данных модель может вернуть `status:manual_review`, `results:null` и причину. Приложение показывает «Нужен ручной разбор» (`Review`), не создаёт нулевую оценку/N/A, исключает запись из текущих средних и продолжает пакет. Прежний результат сохраняется отдельно. Невалидная структура остаётся ошибкой обработки. Изменение версии инструкций делает предыдущие оценки устаревшими без автоматического вызова AI; связанные ожидающие апелляции сохраняются в истории как `SUPERSEDED`, чтобы не блокировать новую оценку. После неё можно подать новую апелляцию.

Использован `response_format=json_schema` со строгой схемой вместо устаревшего JSON mode из текстового задания: [официальная документация OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs). Модель сохранена `gpt-4o`, температура 0.

При отказе проверки приложение показывает конкретную безопасную причину в карточке и после обновления страницы. В техническом журнале хранится только код ошибки; ответ модели, цитаты, исходные персональные данные и таблицы скрытия в журнал не записываются. Подготовка запроса сохраняет порядок полей JSON-схемы (решение перед рекомендацией); каноническая сортировка применяется только для хешей.

## API

Обычное чтение диалогов и чек-листа сохраняет демонстрационный режим доступа. Для действий передавайте `X-Role: operator` или `X-Role: supervisor`. Для руководителя при настроенном `QA_SUPERVISOR_TOKEN` также нужен `X-Supervisor-Token`; эта серверная проверка защищает в том числе историю, поиск и запросы AI-помощника, а не только запись. Переключение роли в браузере само по себе не является авторизацией.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Состояние, режим доступа и бюджет |
| GET | `/api/conversations` | Индекс, `language`, `channel`, `status`, `search`, `gross_only=true` (только актуальные положительные флаги) |
| POST | `/api/conversations/extract?filename=...` | TXT/DOCX/PDF/JSON до 5 МБ: тело запроса — байты файла; возвращает извлечённый текст, только QA |
| POST | `/api/conversations/import` | Добавляет `{title,text,language,channel}` к текущим диалогам, только QA; не вызывает ИИ |
| GET | `/api/conversations/{id}` | Транскрипт, оценка, апелляции и история |
| GET | `/api/conversations/{id}/audio` | MP3, локальный кэш и HTTP Range |
| GET / POST | `/api/checklist` | Чек-лист; POST `{version, criteria}` с защитой от потери конкурентных правок |
| POST | `/api/ai/prepare` | Подготавливает точное превью и временный `preview_id`; `purpose`: `evaluation`, `batch`, `practice`, `assistant_search`, `assistant_recommendations`; необязательный `redactions:[...]` |
| GET / POST | `/api/ai/privacy` | Настройки скрытия и запрета внешней обработки; изменение только руководителем |
| POST | `/api/evaluate/{id}?force=false` | Оценка или кэш, только QA; для новой отправки нужен `X-AI-Preview` |
| POST | `/api/evaluate-batch` | `{conversation_ids:[...]}`; превью всего пакета и `X-AI-Preview`, без превышения оставшегося бюджета |
| POST | `/api/assistant` | `{preview_id}`; подготовленный поиск или рекомендации, только руководитель |
| POST | `/api/assistant/filter` | `{filters}`; локальное применение разрешённых условий, без AI, только руководитель |
| GET | `/api/assistant/history` | Последние 40 сообщений, отдельный бюджет и режим доступа, только руководитель |
| GET | `/api/appeals` | Общий список апелляций со статусами и доступностью диалога; проверка роли |
| POST | `/api/appeals/submit` | `{conversation_id, criterion_id, evaluation_id, comment}` |
| POST | `/api/appeals/resolve` | `{conversation_id, criterion_id, appeal_id, action, new_score, is_na, resolution_comment}` |
| GET | `/api/audit?conversation_id=...` | Журнал с предыдущими и новыми значениями, только QA |
| POST | `/api/dataset/refresh?group_id=DEV` | Загрузка/обновление одной группы через сервер, только QA |
| POST | `/api/dataset/import` | Добавление ответа организаторов из JSON до 5 МБ, без оценки; остальные наборы сохраняются, только QA |

`evaluation_id` и `appeal_id` дополняют минимальное задание, чтобы не применить решение к устаревшей оценке. Повторная ожидающая апелляция по критерию запрещена; повторное разрешение возвращает 409. Изменение правил помечает ожидающие апелляции `SUPERSEDED`, история сохраняется. При ожидающей апелляции принудительная переоценка заблокирована до её разрешения.

Для новой одиночной оценки сначала отправьте `POST /api/ai/prepare` с `{purpose:"evaluation", conversation_id:"...", force:false, redactions:[]}`. Покажите пользователю все `requests`, дождитесь подтверждения и передайте полученный `preview_id` как `X-AI-Preview` при `POST /api/evaluate/{id}`. Для повторной оценки `force:true` должен совпадать в подготовке и отправке. Для пакета используется `purpose:"batch"` и тот же список `conversation_ids`; для помощника — отдельные назначения и `POST /api/assistant`. В помощнике нажатие «Отправить» сразу запускает подготовку и отправку по текущим настройкам защиты, без модального подтверждения. Это относится и к кнопке подготовки рекомендаций; серверные проверки доступа, бюджета и запрета внешней обработки сохраняются. Актуальный кэш внешнего вызова не требует.

Превью одноразовое, связано с ролью, назначением, исходными данными и версией защиты. Оно хранится только в памяти одного серверного процесса **10 минут**. Перезапуск, истечение срока, смена настройки или исходных данных требуют повторной подготовки (для оценки и тренировки — также подтверждения). Поиск грубых ошибок снимает несовместимый фильтр «Нет оценки ИИ» (а также устаревшие, ошибочные и обрабатываемые оценки), сохраняя язык и канал. Явный последующий запрос таких статусов снимает фильтр грубых ошибок. На вопрос о повторяющихся ошибках модель возвращает разрешённую команду `summary`, после чего сервер считает замечания по критериям и финальным оценкам. Сводка учитывает выбранные фильтры, показывает охват, применимые оценки и ссылки на доказательства; N/A, устаревшие и отсутствующие оценки не считаются ошибками. Сырые ответы модели в технический журнал не записываются: ошибки помощника различаются фиксированными кодами причины. Само наличие `preview_id` не отменяет проверку роли, токена, лимитов и состояния данных при отправке.

Организаторская audio_url может вести на HTML-плеер. Сервер извлекает только `audio/source src`, разрешает наблюдавшийся HTTPS-хост `freedomholdingcorporation.crm11.dynamics.com`, скачивает до 60 MB и обслуживает файл с Range. HTML/JavaScript организаторов в приложение не внедряются.

## Проверка

```powershell
python -m pytest -q
node --test tests/frontend.test.cjs
node --check frontend/app.js
```

Серверные тесты используют синтетические данные и фиктивные ответы модели без платных вызовов: формулы, N/A, ступени, нулевой знаменатель, отдельный флаг, верификация цитат, лимит/кэш, обе ветки апелляции, версии правил, роли, откат при ошибке записи и безопасное извлечение аудио. Дополнительно проверены команды поиска и уточнения, финальные значения после апелляций, охват и статусы, знаменатели рекомендаций и ссылки, скрытие данных, запрет внешней обработки, ошибки подготовки, пакетная и повторная оценка, доступ и оба бюджета. Клиентские тесты на Node.js проверяют фильтры, запоздалые ответы, выбор диалога, отмену перемотки, адресацию апелляции, ручное решение, помощника и подтверждение актуального превью.

Для этой доработки: **329 серверных и 73 клиентских теста прошли**. Автоматические проверки не выполняют платные вызовы. Проверены подмена цитат, недопустимые ссылки, перепутанная нумерация, повреждённая карта скрытия, длинные фрагменты с RU/KZ/EN-данными, повторная/пакетная оценка, апелляции и экспорт.

08.11.2026 каждый платный диагностический вызов был отдельно разрешён пользователем. Вызов по p1-ru-002 воспроизвёл отказ проверки цитаты. Затем первый вызов по p1-ru-001 выявил смещение ссылок из-за одновременного наличия `index` с нуля и `turn` с единицы; результат помечен недействительным в истории, учёт расходов сохранён. После удаления двойной нумерации следующий вызов по p1-ru-001 завершился HTTP 200 за 4,6 секунды: 8 критериев, все цитаты и время совпадают с источником, ссылки ведут к правильным репликам. Проверены сохранение после обновления страницы и переход из цитаты в переписку. Автоматических повторов не было.

После этой диагностики правило завершения уточнено в версии `2026-11-08.3`: добавлены явная проверка двух элементов, отрицательные примеры вежливого прощания на RU/KZ/EN и положительные примеры завершения в нескольких репликах. Уточнение действует в стандартном чек-листе, инструкциях оценки и подсказке JSON-схемы; упражнения получают тот же критерий. Сохранённый исходный критерий мигрирует с сохранением веса; пользовательские изменённые правила не перезаписываются. Ранее сохранённые оценки помечаются устаревшими, без подмены ответа модели или автоматической переоценки. После этого уточнения платные запросы не выполнялись.

Эта проверка подтверждает исправление передачи доказательств, а не точность всех оценок модели. В успешном диагностическом ответе модель ошибочно засчитала `closure=true` за «Пожалуйста. Хорошего вечера!»; по заданному правилу без итога/предложения помощи это `false`. Смысловые оценки по-прежнему требуют проверки аудитором; вручную подменять ответ модели или автоматически объявлять его достоверным приложение не должно. Полнота распознавания персональных данных на реальном корпусе также не измерена.

### Пропускная способность локальной версии

Изолированный замер на этом Mac (1 процесс Uvicorn, 65 синтетических диалогов по 10 реплик, 20 актуальных оценок, 200 запросов на сценарий): список диалогов — 340 запросов/с при одном клиенте и 326 запросов/с при 8 параллельных; p95 соответственно 3 и 34 мс. Локальное применение готовых фильтров — около 687–692 запросов/с. Это короткий замер чтения на небольшой выборке, не число одновременно работающих пользователей и не скорость AI. Отчёт сохранён локально в `output/artifacts/local-throughput.json`.

Оценка диалогов выполняется по одному запросу одновременно; пакет последовательный. Дополнительная одновременная оценка получает 409, очереди задач нет. Помощник также обрабатывает один активный запрос; упражнения защищены от одновременной проверки одного задания. Реальная скорость анализа зависит от модели и квот провайдера, без платных запросов она не измерялась. При среднем времени полной оценки T секунд ориентир — 60/T диалогов в минуту: например, **если** T=20 секунд, 3/мин или 180/час. Хранилище JSON рассчитано на один серверный процесс; увеличение workers без смены хранения и синхронизации не поддерживается.

Pytest собирает только `tests/test_*.py`; autouse-фикстура подменяет ключ и блокирует платный метод OpenAI. Временные скрипты исключены из сбора.

`scripts/live_smoke.py` сохранён для отдельной, осознанной проверки реального провайдера, но в этой доработке проверялись только его синтаксис и `--help`. Он работает только с локальным API, принимает не более трёх ID, соблюдает серверные настройки и лимиты и останавливается на первой ошибке:

```powershell
python scripts/live_smoke.py p4-ru-002 p1-kz-001 p1-en-001
```

Для каждого диалога без актуального кэша скрипт показывает полный подготовленный JSON в интерактивном терминале. Отправка произойдёт только после ввода `SEND <ID>`. Команда `HIDE` позволяет добавить скрываемое значение и увидеть заново подготовленный запрос; пустой ввод отменяет отправку. Неинтерактивная отправка и автоматическое подтверждение не поддерживаются. При настроенном QA-токене передайте его через переменную окружения `QA_SUPERVISOR_TOKEN`, не как аргумент команды. Сводка с ID, баллами, статусом кэша и usage сохраняется в игнорируемый `output/validation.json`; исходный текст, превью и значения для скрытия в отчёт не записываются. Актуальные оценки используются из кэша.

Исторические результаты прежней платной проверки и ограничения EN описаны в [VALIDATION.md](VALIDATION.md); это не результаты текущей доработки.

## Загрузка своего диалога

На главной нажмите **«Загрузить диалог»**. Выберите TXT, DOCX, JSON или PDF с текстовым слоем (до 5 МБ; PDF до 50 страниц) либо вставьте текст вручную. Укажите название, язык и тип диалога, проверьте извлечённый текст и нажмите **«Добавить диалог»**. Для PDF-сканов распознавание изображений не выполняется. Исходный файл не сохраняется, сохраняется проверенный текст.

Каждую новую реплику начните с роли; время необязательно:

```text
Клиент: Где посмотреть мой тариф?
Оператор: Здравствуйте! Откройте раздел «Кабинет».
Клиент: Спасибо, нашёл.
```

При наличии времени используйте `00:15 Клиент: ...` или `[00:15] Клиент: ...`. Поддерживаются также Client/Customer, Operator/Agent, Бот/Bot и Система/System. Без времени сохраняются ссылки «Реплика 1», «Реплика 2» и т. д.; выдуманных секунд нет. Нужны реплики клиента и оператора. Лимит — 100 000 символов и 2000 реплик на диалог.

JSON принимает объект диалога с `transcript`, массив диалогов, массив реплик, `{records:[...]}` и ответ организаторов `{isSuccess:true,data:{records:[...]}}`. Вместо `transcript` можно передать `messages`, вместо `speaker`/`text` — `role`/`content`; участники должны быть указаны явно. Для одного диалога поддерживается также поле `text` с подписанными репликами. Язык — RU/KZ/EN, канал — `agent chat`/`voice call`. Если язык не указан, выберите его в форме.

При нескольких диалогах появляется выбор **«Диалог из файла»**: кнопка добавляет только выбранный диалог. Исходные роли, текст и время структурированного JSON сохраняются, пока пользователь не редактирует текст в форме; после редактирования текст разбирается по указанным выше подписям. Оценки, история и ссылки на аудио из JSON не переносятся. В форме есть скачиваемый [пример JSON](frontend/dialogue-example.json).

Новый диалог открывается без оценки, анализ запускается отдельно в пределах прежнего бюджета. Загрузка сама по себе не вызывает OpenAI. Загруженные диалоги сохраняются при перезапуске и обновлении группы организаторов. Существующие оценки не перезаписываются. Поиск учитывает название загруженного диалога.

## Рабочие разделы

Текстовое меню открывает диалоги, апелляции и аналитику. Причины снижения балла показаны перед полным списком критериев; ссылки ведут к подтверждающим репликам. Общий обзор включает таблицу по наборам, охват и назначение каждого набора. Аналитика считает только актуальные оценки выбранной группы (или всех наборов при выборе «Все диалоги»), сохраняет нулевые баллы и показывает прочерк при отсутствии рассчитанных баллов. Это статистика загруженных диалогов, а не оценка точности модели по Ground Truth.

Светлая тема используется по умолчанию, выбор темы сохраняется в браузере. На узких экранах список диалогов открывается отдельной панелью. Внешний вид адаптирован для рабочих задач контроля качества; ограничения доступа прототипа описаны ниже.

## Структура и ограничения

```text
backend/main.py             API, атомарное JSON-хранилище, бюджет, апелляции, аудио
backend/dataset.py          проверка формата датасета без запуска приложения
backend/scoring_engine.py   динамический чек-лист, проверка значений, расчёт
backend/ai_evaluator.py     GPT-4o, строгая схема, проверка доказательств
backend/ai_gateway.py       единая граница внешних запросов, локальное скрытие и связь цитат
backend/ai_requests.py      превью, настройки защиты, бюджеты и API помощника
backend/manager_assistant.py разрешённые команды, поиск и серверные факты рекомендаций
frontend/                  HTML, CSS, vanilla JS, плеер и редактор
tests/test_cqa.py           проверки без OpenAI
tests/test_manager_assistant.py синтетические проверки поиска и рекомендаций
tests/frontend.test.cjs     проверки клиентской логики без браузера и сети
scripts/                   импорт и явная платная проверка
data/                      локальные данные, ключей нет; исключено из Git
.env                       ключ и подписанный URL; исключено из Git
```

Это прототип для локальной демонстрации, а не проверенное промышленное развёртывание. По умолчанию роли переключаются без входа; оператор не привязан к конкретному сотруднику. QA-токен защищает действия супервизора, включая чтение истории помощника и его фильтры, но не является полноценной аутентификацией или индивидуальным разграничением доступа. Обычные API чтения сохраняют демонстрационный режим, история помощника общая для локальной установки. Для банковской эксплуатации нужны SSO, привязка диалогов к сотрудникам, полноценный RBAC, шифрование, политика хранения, защищённый неизменяемый аудит, БД и независимая проверка качества ИИ.

Используйте **один** Uvicorn worker/процесс на файл хранилища. Потоковые блокировки, билеты превью и атомарная замена JSON работают внутри процесса; межпроцессная синхронизация не реализована. Билеты превью истекают через 10 минут и теряются при перезапуске. Журнал локальный, не защищён от изменения владельцем файлов.

HTML/CSS/JS не зависят от сборщика или внешнего CDN. Для Dynamics 365 требуется зарегистрировать web resource, настроить HTTPS API/CORS и задать `window.CQA_API_BASE` перед `app.js`; пути `/static/...` в HTML нужно заменить на пути зарегистрированных ресурсов. Интеграция в реальном Dynamics tenant в этой работе не проверялась. Ключ OpenAI остаётся на сервере.

Ни ключ, ни оригинальный датасет, ни подписанные ссылки не включаются в Git. Принудительная отправка `git push --force` из приложенного текста не выполняется.
